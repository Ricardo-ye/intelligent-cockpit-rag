# 智能座舱 RAG 评测工作台｜面试项目介绍

## 项目整体介绍

项目面向车载知识问答的检索、生成和质量评估。目标不是把所有问题交给 Agent 自主规划，而是在知识来源、检索路径和评测口径可控的前提下，比较不同 RAG 配置的效果、延迟、稳定性与成本。

技术栈为 Python、Streamlit、TF-IDF/SVD 或 OpenAI 兼容 Embedding、BM25、FAISS、OpenAI 兼容 LLM 与 pytest。主流程为：文档摄入 → 分块 → 向量/关键词混合检索 → 可选重排与上下文压缩 → 生成或离线抽取 → 检索、答案、忠实度和相关性评测 → 报告导出。

## 我的职责与关键产出

- 建立离线与真实 LLM 双链路，保证无 Key 时仍可完成真实检索和评测；
- 记录请求配置与实际生效配置、失败、降级、重试、token 和延迟，避免“只报好看的平均数”；
- 增加版本化价格表读取与成本估算，并支持同配置跨模型对照；
- 明确成本估算边界：仅覆盖已记录文本 token，不伪造 Embedding、平台最低消费、税费等金额。

## 亮点、难点与客观局限

亮点是评测口径透明：报告区分词法代理与 LLM 判官，区分上下文压缩耗时与净生成耗时，且把降级写入结果。难点在于模型价格和模型能力都会变化，因此价格不写死在代码中，实验必须带价格表版本、相同题集和相同检索配置。

当前不足是跨模型结果只有在同一题集、参数、价格日期下才可比较；真实用户可用性也不能由离线评测替代。改进方向是增加固定基准集、P50/P95 指标、Embedding 成本记录和真实任务成功率研究。

## 3–5 分钟讲述要点

“这是一个面向智能座舱知识问答的 RAG 评测工作台。我没有把它包装成 Agent，因为检索、证据引用和安全降级的路径需要稳定可测，固定 Workflow 更合适。我的重点是把效果、延迟、稳定性和成本放在同一份可复现实验报告中：不仅记录答案指标，还记录模型调用、token、重试、截断、压缩耗时和配置降级。

针对成本不能只看 token 的问题，我增加了外置、版本化价格表。报告只在存在明确价格表时计算金额，否则明确标为不可估算；同时支持相同配置下跨模型比较，避免因为题集或检索参数变化而产生伪结论。这个项目体现的是我对 AI 系统评测口径和工程边界的重视。”
